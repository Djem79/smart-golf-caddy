# Sign in with Apple — подготовка (App Store 4.8)

Требование применимо: мы используем Google Sign-In для основного аккаунта,
значит обязаны предложить равноценный приватный способ входа. Исключения
(только собственная авторизация / корпоративные приложения) — не наш случай.

Платный аккаунт разработчика нужен только для ВКЛЮЧЕНИЯ. Код, кнопку,
обработку ошибок и тесты готовим сейчас.

## Что берём из документации Apple (проверено)

**Кнопка (HIG).** Минимум 30×140 pt, радиус 6 pt при минимальном размере.
Три стиля: чёрная, белая, белая с обводкой. Тексты — только «Sign in with
Apple» / «Sign up with Apple» / «Continue with Apple», локализованные
Apple, свои переводы запрещены. Кнопка **не меньше остальных кнопок
входа** и видна без прокрутки. Нельзя перекрашивать, менять логотип,
добавлять свои надписи внутрь.

**Nonce.** Генерируем случайный raw-nonce → в запрос Apple уходит его
SHA-256 → в Firebase передаётся ИСХОДНЫЙ raw. Перепутать нельзя: если
отправить raw в Apple или хэш в Firebase — проверка не пройдёт.

**Имя даётся ровно один раз** — при первой авторизации. Сохранять сразу,
не перезаписывать пустым при повторных входах. Долговременный ключ
личности — стабильный идентификатор Apple, НЕ адрес почты.

**Отзыв токена при удалении (TN3194).** При удалении аккаунта нужно
вызвать `POST https://appleid.apple.com/auth/revoke`. Наш `deleteAccount`
этого не делает — дописать.

**Скрытая почта.** Apple может выдать адрес `@privaterelay.appleid.com`.
Письма туда не дойдут, пока домен отправителя не зарегистрирован у Apple.
Сейчас отправитель — песочница `onboarding@resend.dev`, она точно не
подойдёт: нужен свой домен (уже висит в бэклоге отдельной задачей).

**Связывание аккаунтов.** Тот же адрес → Firebase бросает
`auth/account-exists-with-different-credential`. Правильный путь: попросить
войти прежним способом, затем связать credential. Молча связывать по
адресу нельзя.
Отдельный случай: при «скрыть почту» адрес РАЗНЫЙ, и Firebase создаст
второй аккаунт — автоматически это не решается, нужен явный сценарий
связывания в профиле.

Capability в Xcode, Service ID для веба, активация провайдера в Firebase,
реальный вход. Тесты — на моках; живая проверка входит в чек-лист T4.
